# 课程设计思想：生成式软件工程与 Agent 工作台

更新：2026-10-29。状态：持续更新的设计参考；不是已完成的重构方案。

来源为 [jyy《生成式软件工程》2026 秋季课程](https://jyywiki.cn/GSE/2026/)。本次查阅首页列出的第 1–10 讲与 Lab 1、Lab 2。讲义可能继续修改，本文件记录本次阅读后的项目化提炼，不保存讲义全文，也不把课堂案例自动转为产品需求。

下文“课程启发”是对讲义的概括；“项目应用”是本项目的设计判断。编号用于需求、设计和后续决策之间的追踪。

## 1. 可持续采用的原则

### P01：意图、规格、实现与证据保持联系

课程启发：能运行的演示可能仍然偏离真实需要；省略的重要决定应及时显露。见 [第 1 讲](https://jyywiki.cn/GSE/2026/lect1.md)。

项目应用：每项需求说明输入、预期行为、失败行为、完成证据，并关联负责模块。“已实现”“已验收”分开记录；模型说完成不能替代成果检查。

### P02：上下文有来源、作用范围和预算

课程启发：模型面对整份上下文；长期规则、任务方法和引用材料应区别组织，更多规则不一定更有效。见 [第 2 讲](https://jyywiki.cn/GSE/2026/lect2.md)。

项目应用：主会话、知识检索、领域材料和 Skills 各有边界。网页、聊天分享和论文是资料，不获得执行权限。先保存有用规则，再考虑按需加载；不靠提示词承担可由程序检查的约束。

### P03：保存可解释的项目状态

课程启发：项目快照需要让源码、接口与配置共同构成可重建的状态。见 [第 3 讲](https://jyywiki.cn/GSE/2026/lect3.md)。

项目应用：公开版本保存源码、依赖说明和文档；密钥、个人数据和运行产物分离。重构需要记录迁移与回退方法，不能只留下一个“改好了”的结论。

### P04：追踪变化，明确并行的共享边界

课程启发：文件历史不自动解释设计理由；工作目录隔离也不能代替接口和依赖协调。见 [第 4 讲](https://jyywiki.cn/GSE/2026/lect4.md)。

项目应用：需求 ID 关联设计和模块，重要决定保留理由。运行中的 Subagent 隔离上下文，但共享线程、磁盘和外部服务；不能把这种隔离描述为进程沙箱。

### P05：尽早接触最危险的不确定性

课程启发：原型与短周期反馈让运行约束较早暴露；开发各环节形成依赖，不要求一次性完成全部阶段。见 [第 5 讲](https://jyywiki.cn/GSE/2026/lect5.md)。

项目应用：重构按可交付路径分段，优先处理重复状态、恢复和来源完整性。网络、登录、依赖安装及文件一致性属于行为规格；写完配置或打开页面都不足以证明流程通过。

### P06：换一种表示，让变化找到归属

课程启发：合适的中间表示能隔开输入、计算与输出；当前值还可能隐藏历史与规则。见 [第 6 讲](https://jyywiki.cn/GSE/2026/lect6.md)。

项目应用：保留 `SourceBlock → SummaryBundle → 领域成稿`。视频秒数、论文页码、消息编号、学习记录编号由各读取器建立；公共总结引擎不负责下载材料。当前项目状态不能冒充历史周报中的新增进展。

### P07：设计可组合的契约，分离事实和展示

课程启发：共同接口使工具可以组合；业务状态、界面状态与由它们计算的视图应明确区分。见 [第 7 讲](https://jyywiki.cn/GSE/2026/lect7.md)。

项目应用：桌面对话、独立页面和定时入口复用应用服务；页面不维护另一套业务事实。模型提出结构化动作，程序校验并执行；程序计算统计值，模型解释内容。领域差异保留在相应适配器中。

### P08：长任务依靠可恢复的工作状态和有效反馈

课程启发：反复运行只有结合验收与停止条件才有价值；工作区应留下接手下一轮所需的事实。见 [第 8 讲](https://jyywiki.cn/GSE/2026/lect8.md)。

项目应用：明确轮数、时间、取消与结果保留规则。当前采用有界 Agent Loop；不因课程介绍 Ralph Loop 就增加无限外层循环。未来验证应包含失败路径；本轮只整理文档，不因此新增或执行测试。

### P09：Harness 的公共对象和协作语义优先于插件数量

课程启发：共同事件可以形成消息、业务和界面投影；插件协作还需约定时序、所有权及副作用。见 [第 9 讲](https://jyywiki.cn/GSE/2026/lect9.md)。

项目应用：先界定会话、运行实例、操作、成果和来源。当前已有事件表与注册表，尚无统一事件架构。重构可评估公共运行事件，但不预先承诺全量事件溯源、插件市场或更换为 dsh。

### P10：局部演化，保留决策理由

课程启发：扩展点也有成本；架构要结合时间、兼容与实际故障不断调整。设计记录应帮助下一次决策。见 [第 10 讲](https://jyywiki.cn/GSE/2026/lect10.md)。

项目应用：重要变化使用简短 ADR，描述背景、备选、取舍、后果与替代条件。用现有场景评价修改成本；保留旧角色、成果路径和数据迁移语义，不以拆文件数量判断重构成果。

### P11：个人助手的成长要能读、能改、能追溯

课程启发：个人资料检索、能力组合和可修改经验是持续助手的组成部分。见 [Lab 1](https://jyywiki.cn/GSE/2026/lab1.md)。

项目应用：知识保留来源和编辑历史；普通聊天入库由用户选择；成功方法可由用户审阅后沉淀成 Skill。课程中的邮箱、eHall、手机联动不属于本项目已确认范围。

### P12：更多计算必须带来可比较的收益

课程启发：更高 effort 应服务于探索、查证与修正，并与直接求解比较效果及成本。见 [Lab 2](https://jyywiki.cn/GSE/2026/lab2.md)。

项目应用：`effort`、候选方案比较、独立审查和更深研究列为设计候选，当前没有这些产品保证。后续若采纳，先定义任务样例、质量判据、预算与停止条件，不能用模型调用次数证明质量提升。

## 2. 在本项目中的采用状态

| 主题 | 已有基础 | 仍需设计或核验 |
| --- | --- | --- |
| 可检查交付 | 输入校验、来源编号、文件检查、任务记录 | 统一完成证据和验收记录；语义真实性不由格式检查保证 |
| 公共中间表示 | `SourceBlock`、`SummaryBundle` | 契约版本、稳定来源身份、成果元数据统一 |
| 上下文隔离 | 领域独立历史、Skills、检索预算 | 工具与规则按需发现；模型适配完整解耦 |
| 事实与投影 | 消息、来源、知识版本、程序统计 | 跨状态表和磁盘文件的一致性、查询投影所有权 |
| 重试与恢复 | 成功工具缓存、部分请求指纹、重启中断标记 | 跨入口幂等、未知结果处理、阶段恢复和补偿 |
| 演化与组合 | Agent/Capability/应用注册表、旧路径兼容 | 新增能力仍有硬编码；扩展边界需要收敛 |
| 计算换质量 | 分块整合、有界工具循环 | effort 与候选审查尚未实现，需单独立项 |

## 3. 讲义更新如何进入需求

1. 更新课程首页清单与本次阅读日期；注明新增或修改的讲次。
2. 保持 P01–P12 编号稳定；新增原则追加编号，替代原则留下理由和替代关系。
3. 先区分原文观点、项目推论和可执行需求；课程中的设想与实验不直接升级为产品承诺。
4. 修改根目录需求文档中的设计思想摘要，并关联受影响的需求 ID 和设计章节。
5. 改变模块边界、数据语义、权限或恢复方式时先形成设计提案；用户确认后的选择再记入 ADR。
6. 验证结论独立记录。课程新增内容和文档更新不会自动触发代码变更、在线安装或后台定时更新。
